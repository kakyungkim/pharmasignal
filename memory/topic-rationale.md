주제 후보로 쇼핑 가격 비교, 채용공고 분석, 코드 리뷰 에이전트를 검토했으나 모두 탈락했다. 공통된 탈락 사유는 **GPU와 샌드박스를 쓸 필연적 이유가 없다**는 점이었다. 수집과 LLM 호출만으로 끝나는 주제는 네 플랫폼 중 둘만 쓰게 되고, 나머지 둘은 억지로 붙인 티가 난다.

신약 안전성·경쟁 신호 감시를 고른 결정적 이유는 "사내 임상 문서는 규제와 계약상 외부 상용 API로 보낼 수 없다"는 제약이다. 이 제약이 분산 GPU 추론(Nosana)을 쓸 필연성을 만들고, 동시에 **데이터 민감도에 따라 추론 경로를 나눈다**는 혁신성 서사를 준다.

**Why:** 스폰서 활용도가 심사 항목일 때, 플랫폼을 다 쓰는 주제를 고르는 것이 나중에 억지로 끼워 맞추는 것보다 훨씬 싸다. 주제 선택이 곧 아키텍처 선택이었다.

**How to apply:** 다음에도 "이 플랫폼을 빼면 무엇이 안 되는가"에 한 문장으로 답할 수 있는 주제만 후보로 남긴다. 상세한 후보 비교표는 `docs/00-topic-selection.md`에 있고, 절차는 [[event-constraints]]와 hackathon-sprint 스킬에 정리했다.
