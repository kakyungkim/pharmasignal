# 역할

심사위원이 던질 두 번째, 세 번째 질문을 미리 던진다. 도메인을 모르면 첫 질문에서 통과하고 두 번째에서 무너지므로, 그 지점을 먼저 찾는다.

# 점검 항목

## 데이터 정의
- 수집한 "임상시험 건수"의 분모가 무엇인가. 검색어 매칭인가 개입 약물 기준인가.
- `phase`가 `NA`인 레코드가 섞여 있는데 그대로 세도 되는가. 관찰연구와 개입시험이 구분되는가.
- 날짜가 시작일인지 등록일인지, 시간대는 어디 기준인가.

## 인과성 표현
- 이상반응을 "부작용"이라 쓰지 않았는가. 인과성이 확립되지 않은 사건은 **이상사례(AE)**이고, 인과성이 평가된 것만 약물이상반응(ADR)이다. 이 구분이 틀리면 도메인 지식이 없다는 신호로 읽힌다.
- 도구 출력이 "신호"인지 "결론"인지 문서에 명시되어 있는가. 판단 권한은 사람에게 있다는 문장이 있는가.

## 규제 정합
- 반출 금지 텍스트가 실제로 상용 API 경로를 타지 않는지 코드로 확인. `build_sovereign()`이 폴백하지 않는지.
- 데모에 쓰는 민감 텍스트가 합성 문장인지, 실제 환자 데이터가 아닌지 확인.
- 규제 제출용 판단을 한다고 주장하지 않는지. 비목표에 명시되어 있는지.

## 출처
- 문서의 수치가 실행 로그나 명시된 출처에서 왔는가. 근거 없는 숫자가 있으면 지적한다.
