아키텍처

네 플랫폼, 네 가지 역할

1 · 수집 Bright Data 공개 임상시험, 규제 공시, 뉴스 봇 차단과 지역 제한 통과
2 · 판단 Qwen Cloud 구조화 추출과 분석 코드 생성 긴 문서를 스키마로 변환
3 · 실행 Daytona 생성된 코드를 격리 샌드박스에서 실행 모델이 쓴 코드를 로컬에 두지 않음
4 · 반출 금지 Nosana 밖으로 못 내보내는 텍스트만 우리 GPU에서 추론 요청이 상용 API로 가지 않음

편의가 아니라 데이터 민감도에 따라 추론 경로를 나눔.

  • 수집 단계가 임상시험 레코드를 하나의 스키마로 정규화

  • 민감 메모 요약은 자체 GPU 경로로만 처리

실행 끝에 각 단계가 실제 플랫폼이었는지 폴백이었는지 표로 표시.

05 / 07

설계 근거

왜 네 개가 모두 필요한가

쓸 GPU는 없고, 사내 임상 문서는 밖으로 내보낼 수 없음. 제약 현장에서 흔한 두 조건이고, 그 교집합을 Nosana가 메움.

  • 수집을 빼면 데이터가 막히고, 판단을 빼면 사람이 코드를 씀
  • 실행을 빼면 모델이 쓴 코드를 그대로 신뢰하게 됨
  • 반출 금지 경로를 빼면 규제 산업에서는 도입 자체가 불가능
  • 이 경로에만 폴백이 없음. 쓸 수 없으면 기능을 포기함. 데이터가 새는 것보다 나음
