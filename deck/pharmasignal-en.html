03 / 10

The larger wall

Internal clinical documents cannot leave

Automate the public analysis and the data that matters most is still out of reach

What blocks AI in pharma is not model quality. It is this export restriction, and it usually arrives alongside a team that has no GPU on hand.

04 / 10

The approach

Split the inference path by data sensitivity

1 · CollectBright DataTrial registries, filings, and a literature search for adverse eventsBot blocking and geo limits stand in the way
2 · ReasonQwen CloudExtracts a schema and writes the analysis code itselfLong documents, no two formatted alike
3 · ExecuteDaytonaRuns the generated code in an isolated sandboxModel-written code never touches the host
4 · RestrictedNosanaRestricted text never reaches a commercial providerWithout it, restricted documents cannot be touched at all

Public data goes through commercial APIs. Restricted text is sent only to an endpoint we designate.

The idea is not new. LiteLLM and Portkey ship the same routing, and PAPILLON (NAACL 2025) studies the same problem. What differs here is the default: cross-tier fallback is forbidden.

05 / 10

By design

This path alone has no fallback

build_sovereign() → None unavailable means we drop the feature and skip the stage

Every other stage degrades gracefully. A fallback here would quietly leak restricted text to a commercial API, so losing the feature is the better trade.

06 / 10

Verification

Code re-checks what the model produced

An established technique. PAL, PoT and LEVER set the principle, and it has already been applied in pharmacovigilance.

[crosscheck] recomputing the aggregates with fixed logic 11/11 agree

We never ask the model whether its own numbers are right. The same aggregates are recomputed in fixed code and compared, and any disagreement is printed as it is.

Every run also writes a ledger recording which provider served which stage.
