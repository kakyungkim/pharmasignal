# 04. Nosana GPU 연결 절차

> 4단계(데이터 주권) 경로를 실제로 살리기 위한 설정. 대기 시간이 가장 길어 **제일 먼저 착수**한다.

## 왜 이게 중요한가

이번 작업 환경에는 쓸 만한 GPU가 없다. 특별한 사정이 아니라 대부분의 현장이 그렇다. Intel Core i5-1038NG7에 Iris Plus 내장 그래픽, VRAM 1.5GB이고 PyTorch MPS도 지원되지 않는다(확인 완료). 로컬에서 오픈웨이트 LLM을 GPU로 돌리는 선택지는 없다.

이것은 약점이 아니라 **발표에서 쓸 논거**다.

> 쓸 GPU가 없고, 사내 임상 문서는 외부 상용 API로 보낼 수 없음. 제약 현장에서 흔히 겹치는 두 조건이고, Nosana가 그 교집합을 메움.

## 연결 절차

### 1. 계정 (2분)
[deploy.nosana.com](https://deploy.nosana.com/) 접속. **Google 로그인이 가능하므로 Solana 지갑을 새로 만들 필요가 없다.** 지갑 인증도 선택지로 있지만 시간상 Google 로그인이 빠르다.

### 2. 크레딧
크레딧은 선불식으로 컴퓨트 비용에 쓰인다. 행사에서 제공하는 크레딧 코드가 있으면 계정 페이지에서 등록한다. **스폰서 부스에 직접 물어보는 것이 가장 빠르다.**

### 3. 배포 (3~10분)
**템플릿은 `DeepSeek-R1`을 쓴다.** 공식 LLM 배포 가이드가 이 템플릿을 기준으로 쓰여 있고, 서빙하는 모델이 `DeepSeek-R1-Distill-Qwen-1.5B`라 Qwen 계열이다. 1.5B로 작아 기동이 빠른 것도 마감이 임박한 상황에 맞는다.

1. 좌측 사이드바 **Deploy** 클릭
2. 이름 입력 후 템플릿에서 **DeepSeek-R1** 선택
3. GPU 선택 (가이드 예시는 NVIDIA 4090)
4. 기본 설정 그대로 (SIMPLE 전략, 복제본 1개)
5. **Create Deployment**

### 4. 엔드포인트 확인
배포가 시작되면 배포 페이지에 **Endpoint URL**이 뜬다. 형식은 `https://<배포ID>.node.k8s.prd.nos.ci` 이고 OpenAI 호환이다. 뒤에 `/v1`을 붙여 `.env`에 넣는다.

```bash
# code/.env
NOSANA_BASE_URL=https://<배포ID>.node.k8s.prd.nos.ci/v1
NOSANA_API_KEY=nosana          # 인증을 요구하지 않으므로 아무 값이나 무방
NOSANA_MODEL=                  # 비워 두면 서빙 중인 첫 모델을 자동으로 쓴다
```

**추론 태그 주의.** DeepSeek-R1 계열은 답변 앞에 `<think>...</think>`를 붙여 보낸다. 닫는 태그 뒤가 실제 답변이라 `providers/reasoners.py`의 `_strip_reasoning()`이 걷어낸다. 다른 추론 모델로 바꿔도 같은 처리가 적용된다.

`NOSANA_MODEL`을 비워 두면 코드가 `/v1/models`를 조회해 첫 모델을 집는다. 모델명을 몰라도 된다.

### 5. 검증
```bash
cd code && PYTHONPATH=src python -m pharmasignal.cli smoke nosana
```
모델명과 `ONLINE` 응답이 나오면 통과. 출력을 `docs/evidence/`에 저장한다.

2. **해커톤 전용 크레딧 코드** — 있는가, 어떻게 등록하는가

## 폴백 사다리

시간이 부족할 때 아래로 한 칸씩 내려간다.

| 순위 | 방법 | 비고 |
|---|---|---|
| 1 | Nosana에 LLM 템플릿 배포 | 목표 상태 |
| 2 | Nosana에 임의 컨테이너로 vLLM 배포 | 템플릿이 없을 때 |
| 3 | ~~로컬 Ollama~~ | **사용 불가.** Homebrew 설치본(0.30.0)에 `llama-server` 바이너리가 없어 모델 로드가 500으로 실패한다. `qwen2.5:3b`를 포함해 모델 4종이 받아져 있으나 실행되지 않는다. 재설치는 시간이 더 들어 포기했다 |
| 4 | 단계 건너뛰기 | 아키텍처 그림으로 역할만 설명. 코드가 폴백하지 않고 건너뛰는 것 자체가 설계 의도임을 보인다 |

로컬 경로가 막혀 있어 **4단계는 Nosana가 살아나지 않으면 4순위로 간다.** 이 사실이 오히려 발표를 단순하게 만든다. 로컬 GPU도 없고 로컬 런타임도 못 쓰는 상황에서 민감 데이터를 처리하려면 Nosana 같은 경로가 실제로 필요하다는 것이 그대로 증명되기 때문이다.
